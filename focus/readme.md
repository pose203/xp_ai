**你对react有什么理解**
React 是一个用于构建用户界面的 JavaScript 库，核心思想是组件化开发和数据驱动视图。它的三大核心特点是：
组件化：将页面拆分为独立的组件，每个组件可复用、易维护，比如一个按钮组件可在多个页面重复使用。
虚拟DOM：通过内存中的虚拟DOM树对比差异，最小化真实DOM操作，大幅提升渲染效率。
单向数据流：数据从父组件流向子组件（通过props），状态集中管理（如配合Redux），避免数据混乱。
React还支持服务端渲染（Next.js）、跨平台开发（React Native），生态丰富，适合大型项目协作。

**请问react的子父通信 兄弟通信如何实现**
子组件通过 props 接收父组件传入的函数（回调函数），触发时将数据传递给父组件。（单向数据流）
子父组件通信（子 → 父）
原理：父组件传递一个回调函数给子组件，子组件通过调用该回调函数将数据传递回父组件。
兄弟通信：
状态提升：将共享状态交给共同的父组件管理，通过props传递给两个子组件。
Context API：创建共享上下文，避免逐层传递props。
第三方库：如Redux或MobX进行全局状态管理。

**讲讲js的特点**
JavaScript 是一门动态类型、弱类型、基于原型链的语言，特点包括：
动态类型：变量无需声明类型，运行时自动推断（如 let a = 1; a = "str"）。

跨平台：通过Node.js可开发后端，结合Electron可开发桌面应用。

**闭包**
闭包是指函数能够访问并记住其词法作用域，即使该函数在其作用域外执行。
内部函数引用外部函数的变量，即使外部函数已经执行完毕，变量也不会被释放。
优点
封装私有变量：避免全局污染。
持久化数据：变量长期存储在内存中（如计数器、缓存）。
缺点
内存泄漏风险：若闭包引用了大对象且未及时释放，可能导致内存占用过高。

**虚拟DOM**
虚拟DOM（Virtual DOM）是真实DOM的轻量级JavaScript对象抽象，用于描述真实DOM的结构、属性和状态。它本质上是一个用JavaScript对象表示的树形结构（称为VNode树），与真实DOM一一对应。
虚拟DOM的核心思想是先在内存中操作JavaScript对象，再通过算法将变化同步到真实DOM，减少直接操作真实DOM的性能损耗。具体流程如下：
创建虚拟DOM
当组件状态（数据）发生变化时，框架（如Vue或React）会重新生成一个新的虚拟DOM树。
对比差异（Diff算法）
框架会将新旧两棵虚拟DOM树进行对比，找出需要更新的部分（如节点增删改）。
局部更新真实DOM
根据对比结果，只更新真实DOM中变化的部分（称为Patch过程），避免全量重绘/重排。


**防抖（Debounce）**
- 对于一个在短时间内会高频触发的事件，我们只让其关联的回调函数执行一次
- 搜索框（input）实时搜索：用户在输入框中连续输入文字时，我们不希望每输入一个字符就向服务器发送一次请求。通过防抖，可以实现在用户“停止输入”一小段时间后（例如 500ms），才整合最终的输入内容，发送一次网络请求，极大地减轻了服务器的压力。

**节流（Throttling）**
- 在这个单位时间内，无论事件被触发多少次，事件处理函数都只会被执行一次。

**react hooks**
- useState: 这是最核心的 Hook。它为函数组件提供内部状态（state）管理的能力
- useEffect: 这个 Hook 用于处理组件中的“副作用”（Side Effects）。
- useContext: 它使得在组件树中进行跨层级的数据传递变得非常简单。useContext 接收一个由 React.createContext 创建的 context 对象，并返回该 context 的当前值。

- useReducer: 在 state 逻辑变得复杂时，useReducer 可以作为 useState 的替代方案。它更适合管理包含多个子值的 state 对象，或者下一个 state 依赖于前一个 state 的场景。它的工作模式和 Redux 中的 reducer 非常相似，有助于将更新逻辑从组件中分离出来。
- useCallback: 它用于性能优化。useCallback 会返回一个被“记忆化”（memoized）的回调函数。只有当它的依赖项数组中的某个值发生变化时，这个回调函数才会重新被创建。这在将回调函数传递给子组件时非常有用，可以防止因为父组件重新渲染导致子组件不必要的重复渲染。
- useMemo: 与 useCallback 类似，useMemo 也用于性能优化。它返回的是一个被“记忆化”的值。它会执行一个函数并记住其返回结果，只有当依赖项改变时才会重新计算。这可以用来避免在每次渲染时都进行高开销的计算。
- useRef: useRef 返回一个可变的 ref 对象。这个对象在组件的整个生命周期内保持不变
- useLayoutEffect: 它的结构和 useEffect 一样，但执行时机不同。

**async await底层原理实现**
- async/await 本质上是通过 Generator 函数和 Promise 的组合来实现的。当我们使用 async/await 时，JavaScript 引擎会将其转换为 Generator 函数的形式。
- async/await 内部有一个自动执行器，它会自动调用 Generator 函数的 next() 方法，直到所有异步操作完成。这个执行器会处理 Promise 的 resolve 和 reject，并相应地调用 next() 或 throw()。

**Promise**
- Promise 是一个代表异步操作结果的对象，它封装了未来才会完成的操作（如网络请求、文件读取等）。它的核心思想是：将异步操作的状态（成功/失败）和结果分离管理，并通过统一的接口处理结果。
